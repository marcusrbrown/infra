# CLI & KeeWeb Testing

## Problem Frame

The `@marcusrbrown/infra` monorepo has zero test coverage — CI only runs lint + typecheck. The CLI has operational commands (`keeweb deploy`) with irreversible effects, the build script handles secret injection and SHA-256 verification, and multiple AI agents contribute changes. Without tests, regressions in flag parsing, build correctness, and deploy preconditions are only caught in production.

## Requirements

- R1. **Test infrastructure**: Add `bun test` scripts to `packages/cli` and `apps/keeweb`. Wire `bun test` into the CI workflow (`ci.yaml`) alongside existing lint + typecheck. No new dependencies — use Bun's built-in `bun:test` module.
- R2. **CLI snapshot tests**: Snapshot test all `--help` outputs (root, `keeweb status`, `keeweb deploy`, `mcp`). Assert all expected commands are registered and discoverable. Test that invalid options produce Zod validation errors with non-zero exit codes.
- R3. **Build pipeline tests**: Test `apps/keeweb/src/build.ts` with mocked `fetch` and a small zip fixture. Assert: `dist/` files are correct, SHA-256 verification catches tampered archives, `DROPBOX_APP_SECRET` is injected into `dist/config.json` only, tracked `config/config.json` template is never modified, empty secret when env var is unset.
- R4. **Deploy command contract tests**: Unit test `keeweb deploy` flag validation: `--nginx` without `--local` throws, `--dry-run` short-circuits before any side effects, local mode requires `SSH_AUTH_SOCK`, remote mode constructs correct `gh workflow run` command. Mock `Bun.spawn` and env vars — no real SSH or GitHub API calls.
- R5. **Status command tests**: Test `keeweb status` check functions — `checkHttpReachability` with mocked fetch (200, 500, network error), `checkContentHash` with controlled fixtures (missing dist, matching hash, mismatched hash, failed remote fetch), `checkLastDeploy` with mocked `gh` output.

## Success Criteria

- `bun test` exits 0 in CI for both `packages/cli` and `apps/keeweb`
- Tests catch a simulated regression (e.g., removing a command registration, breaking SHA verification)
- No test requires network access, SSH, or GitHub API tokens
- Tests run in < 5 seconds total

## Scope Boundaries

- No integration tests requiring real SSH targets or Docker containers
- No test framework beyond `bun:test` — no vitest, jest, or other runners
- No pre-commit test hook yet (CI-only for v1 — add pre-commit in a future iteration)
- No tests for `apps/cliproxy/` (PR #23 not merged yet)
- Executable conventions tests (#6 from ideation) deferred to a separate iteration
- Deploy script (`deploy.sh`) bash testing deferred — only test TypeScript wrappers
- MCP bridge testing deferred — auto-generated by goke, low drift risk

## Key Decisions

- **Bun built-in test runner**: Zero deps, Jest-compatible API, built-in mocking. No reason to add vitest or jest.
- **Snapshot tests for CLI output**: Cheap to write, high compound value. Update snapshots on intentional changes.
- **Test fixture zip for build tests**: Small synthetic zip (not the real 8MB KeeWeb archive) containing minimal files needed to exercise build logic.
- **Mock at boundaries**: Mock `fetch`, `Bun.spawn`, `process.env` — test the logic between them, not the external services.
- **Test file colocation**: `*.test.ts` files next to the source files they test (e.g., `keeweb-status.test.ts` alongside `keeweb-status.ts`).

## Dependencies / Assumptions

- Bun's `mock.module()` can intercept `fetch` for build.ts HTTP mocking
- goke CLI produces deterministic `--help` output suitable for snapshot testing
- Bun's test runner supports `toMatchSnapshot()` for CLI output assertions
